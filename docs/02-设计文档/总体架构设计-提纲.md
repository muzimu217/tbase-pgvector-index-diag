# 总体架构设计（提纲・方向二）

## 1. 分层架构

```
┌─────────────────────────────────────────────┐
│ 输出层  audit_all_vector_indexes() 风险清单   │ ← 零参数，一条 SQL
├─────────────────────────────────────────────┤
│ 规则与建议层  lists 偏离/内存风险/低召回/计划退化 │
├─────────────────────────────────────────────┤
│ 模型层  内存模型(ivfkmeans.c 移植) + 耗时模型   │
├─────────────────────────────────────────────┤
│ 目录内省层  pg_class.reloptions / pg_attribute │
│            .atttypmod / reltuples / pg_am     │ ← 不要求用户输入任何参数
└─────────────────────────────────────────────┘
```

## 2. 关键设计决策（成稿时展开）

| 决策 | 选择 | 依据 |
|---|---|---|
| 形态 | 外部 SQL 工具集（schema + 函数），不做扩展内函数 | 上游 #765/#863 先例 + Kane 原话 |
| 参数来源 | 系统目录自动获取 | 需要帮助的用户恰恰不知道参数（P1-9） |
| 内存模型 | 源码逐项移植，非拟合 | 拟合公式已被证伪（旧版 2162× 偏差） |
| 单位处理 | PG 内存 GUC 裸数字 = kB（C1 修复） | PostgreSQL 文档语义 |

## 3. 数据流

系统目录 → 内省取参 → 模型计算（内存/耗时/建议 lists）→ 规则评估（风险分级）→ 风险清单输出。

## 4. 应用途径

- 建索引前：预测内存，给出 `maintenance_work_mem` 设置建议。
- 建成后：全库体检，发现 lists 偏离/召回风险/计划退化。
- 运维巡检：inventory 视图 + 体检函数纳入例行 SQL。
