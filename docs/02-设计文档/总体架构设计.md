# OpenTenBase pgvector 索引诊断总体架构设计

## 1. 分层架构

```text
输出层       audit_all_vector_indexes()：零参数风险清单
规则层       内存不足 / lists 偏离 / 统计陈旧 / 静态计划风险
模型层       ivfkmeans.c 11 项内存模型 + lists/probes 起点
目录层       pg_class / pg_index / pg_attribute / pg_am / reloptions
验证层       case 状态机 + 原始 stderr + SHA256 + 报告图表
```

输出层不要求用户手工提供 rows、dims、lists 或索引名；目录层从数据库现状取参，模型层只对 IVFFlat 应用源码公式，规则层把结果分类为 risk/warn/info/ok。HNSW 进入同一清单，但不填 IVFFlat 专属字段。

## 2. 模块与数据流

| 模块 | 文件 | 输入 | 输出 |
|---|---|---|---|
| 输入安全 | `scripts/pgvector-index-diagnostics.sh` | 正整数、受限内存单位 | 安全 SQL 参数或退出码 2 |
| 源码模型 | `sql/02_memory_model.sql` | rows/dims/lists | 11 项 breakdown、required MB |
| 目录内省 | `sql/04_catalog_introspect.sql` | 系统目录 | `vector_index_catalog` |
| 零参审计 | `sql/05_audit.sql` | 目录视图、当前 GUC | 风险清单与建议 |
| 验证 harness | `tools/validate_memory_model.sh` | 20 组 TSV、MODE | CSV、stderr、状态 |
| 证据报告 | `report/figures/`、`report/build/` | 入库快照 | 图表和 15 页 PDF |

数据流为：输入校验 → SQL schema/version → 源码模型或目录视图 → 规则评估 → 原始结果归档。`MODE=auto` 只能产生 model-only；`real` 需要真实建索引；`real-threshold` 只在同源检查点前触发错误；blocked/fail 不能被报告脚本改写为 pass。

## 3. 关键设计决策

| 决策 | 选择 | 依据 |
|---|---|---|
| 工具形态 | 外部 schema + SQL/plpgsql | PR #765/#863 治理边界，不改扩展 ABI |
| 参数来源 | 系统目录自动取参 | 用户求助时通常不知道完整参数 |
| 内存模型 | 源码逐项移植 | 旧拟合公式已在 4 个场景失效 |
| 单位 | 裸 PG 内存数字按 kB | W0 单位语义测试 |
| large 验证 | 降低 `maintenance_work_mem` 阈值触发 | 3.7 GiB 端点防 OOM |
| 计划风险 | 静态 `possible_seqscan` | 不冒充 EXPLAIN 结论 |

## 5. 运用途径

建索引前运行模型，先判断 `maintenance_work_mem` 是否低于源码检查点；建成后运行零参数审计，发现 lists 偏离、统计陈旧或索引无效；生产计划和 recall 仍需业务 SQL、ANALYZE、EXPLAIN 与 workload benchmark。工具是决策辅助，不是对所有硬件和数据分布的保证。
