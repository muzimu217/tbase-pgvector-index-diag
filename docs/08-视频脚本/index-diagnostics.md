# 向量索引构建与诊断视频脚本

建议时长：6 分钟。画面素材来自 `docs/07-演示文稿/index-diagnostics.pptx` 与 `report/`。

## 0:00-0:25 开场

画面：标题页，随后切到 `2162× → 20/20 全零`。

旁白：

“这个项目从一个数量级错误开始：旧的 IVFFlat 内存公式在高 lists 场景低估到 2162 倍。我们没有把预测值写进观测列，而是回到 pgvector 源码，重建模型，再用真实后端日志验证。”

## 0:25-1:10 错误从哪里来

画面：旧公式问题页、语义校正页。

旁白：

“错误来自把两个语义不同的量混在一起。samplesSize 按目标容量 maxlen 分配；k-means 矩阵只按采样行数计算。之前的推导用实际行数截断了 samplesSize，所以 8,192 lists 场景的 7,147 MB 被低估成 1,594 MB，32,768 lists 场景的 17,459 MB 被低估成 1,850 MB。”

## 1:10-1:55 模型

画面：T 与 N 公式页。

旁白：

“实现中把 T 和 N 分开。T 等于 max(10,000, 50 乘 lists)，表示目标采样容量；N 等于 min(rows, T)，表示 k-means 实际使用的行数。再叠加小于等于一百万行时的除法分支、大于一百万行时的平方根分支，以及 32,768 的上限，这就与上游检查点一致。”

## 1:55-2:35 验证状态机

画面：predicted → blocked → observed → pass/fail。

旁白：

“验证器有明确状态机。没有后端日志时，observed 为空，状态必须是 blocked；只有读取到原始 stderr，才能进入误差计算。模型值永远不能直接写入 observed。这条限制让实验可证伪，也让报告不会把预测伪装成实测。”

## 2:35-3:20 G4 结果

画面：新旧公式对数轴图、20 组误差图。

旁白：

“矩阵包含 20 组：15 组真实建索引，5 组 real-threshold。每组原始日志都保存在库中，预测值和后端报错来自同一份源码公式，因此 20 组全部是 0.0000% 误差。全零不是把数字填平，而是 SQL 移植逐字节复刻检查点的证据。”

## 3:20-4:05 分层与 OOM 边界

画面：15 real / 5 real-threshold 页。

旁白：

“大内存场景不能在 3.7 GB 的开发机上硬建巨型索引，否则得到的只是 OOM。我们分层处理：小场景真实建索引；大场景把 maintenance_work_mem 降到阈值以下，触发同源报错。后者证明检查点一致，但不宣称巨型索引已经成功构建。”

## 4:05-4:50 G10 零参数审计

画面：审计图、输出边界页。

旁白：

“第二个门禁是 G10。audit_all_vector_indexes() 不接参数，直接从 pg_class、pg_attribute 和 reloptions 取得表名、行数、维度、索引类型和 IVFFlat lists。实测输出包含 rows=1000、dims=3、lists=10、recommended_lists=1、recommended_probes=4，同时返回 HNSW 行。”

## 4:50-5:25 边界和平台发现

画面：HNSW 留空、possible_seqscan、TAP 页。

旁白：

“边界被显式保留。HNSW 的 IVFFlat 专属字段留空；possible_seqscan 是静态目录风险，不是 EXPLAIN 结论；reltuples 是统计估计。TAP 摸底也准确记录为 0/44 通过、1 次 bailout、43 个未执行，根因是 OpenTenBase 的 Cluster.pm 没有传 nodetype，不把它说成 44 个测试全部失败。”

## 5:25-5:55 交付链

画面：需求 → 设计 → 技术 → 验证链路，随后仓库目录。

旁白：

“项目最终形成需求、设计、技术、验证四段可追溯链路。SQL、shell、CSV、stderr、图表、PDF 和哈希清单都能从仓库重建，参数调优说明和 AI 使用报告记录了每次修正。”

## 5:55-6:15 收尾

画面：结论页。

旁白：

“这项工作的核心不是让一个公式看起来漂亮，而是让它回到源码、回到后端、回到可复现证据。20/20 全零和零参数审计，就是这条链路的当前终点。”

## 屏幕文字与录制提示

- 保持 `7147 MB`、`17459 MB`、`20/20`、`0.0000%` 四组数字的原始格式。
- 展示阈值触发时，明确标注“不是巨型索引成功构建”。
- TAP 结果必须读成“0 通过、1 bailout、43 未执行”，不要说“44 失败”。
