# 4. 方法学

方法分为需求边界、源码翻译、分层验证和目录审计四步。先冻结“预测 pgvector 报错检查点”这一目标，明确它不是进程 RSS 上界；再把 `ivfkmeans.c:277-299` 的 11 项分配逐项翻译为 SQL；之后用 small/saturated 的真实建索引和 large 的阈值触发分别验证；最后用零参数目录审计验证工具能否在不知道索引参数时自动取参。

验证器以 case id 为最小证据单位，保存 rows、dims、lists、预测值、validation mode、observed 值、绝对相对误差、状态和原始 stderr。状态机只有 `pass`、`blocked`、`fail`、`model-only` 四类：端点不可用只能是 model-only；大内存组如果没有真实后端原文只能是 blocked，不能用预测值填充 observed。20 组最终 15 组为 `real`，5 组为 `real-threshold`，没有一组把巨型索引成功构建写入结果。

误差定义为 `abs(observed - predicted) / predicted * 100`，门槛为小于 5%。阈值法下 observed 报错和预测值来自同一份 pgvector 源码检查点，因此逐组 0.0000% 不是把模型复制到观测列，而是 SQL 逐字节复刻检查点的结果；原始 stderr 的建表、INSERT、NOTICE、ERROR 前置序列提供了独立证据。

目录审计不要求用户提供 rows、dims、lists 或 probes：从 `pg_class.reloptions`、`pg_index.indkey`、`pg_attribute.atttypmod`、`pg_class.reltuples`、`pg_am.amname` 和关系大小组成目录视图。`possible_seqscan` 只代表静态目录风险；是否实际走顺序扫描必须另用 EXPLAIN 验证。
