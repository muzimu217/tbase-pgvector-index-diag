# 9. 贡献与后续计划

本项目形成三项贡献。第一，把 pgvector `ivfkmeans.c` 的 11 项分配逐项移植为可审计 SQL，并用 20 组后端原始错误完成 G4：15 组真实建索引、5 组阈值触发，误差全部为 0.0000%。第二，实现不带参数的目录审计，从系统目录自动取得 rows、dims、lists、索引类型和关系大小；G10 的 OpenTenBase 实测同时覆盖 IVFFlat 与 HNSW，并主动保留 HNSW 的 IVFFlat 专属字段为空。第三，把输入拒绝、固定 search_path、schema version、TAP 环境边界和原始 stderr 纳入同一可复现交付链。

上游投递计划（G20）采用外部 SQL 工具集路线。上游 PR #765（https://github.com/pgvector/pgvector/pull/765）讨论过 HNSW 内存估算函数，维护者 Kane 的结论是近似公式可以写进 README，但不希望为它增加函数；PR #863（https://github.com/pgvector/pgvector/pull/863）则说明 bench harness 不应混入扩展本体。因此本仓库不把诊断函数硬塞进 pgvector，而是以独立 schema、纯 SQL/plpgsql、一键安装脚本和证据矩阵提交文档/工具 PR。投递包将包含模型推导、ABI 尺寸工具、20 组 CSV 与 stderr SHA256、零参数审计示例和“real-threshold 不等于巨型构建成功”的边界说明；先在本仓库完成维护者可复核的 commit，再根据反馈拆出文档 PR 与工具 PR。

下一条开发线是利用已有 `pg_stat_progress_create_index` 观测 W3 构建耗时，不重造进度接口。TAP shim、HNSW 推荐增强和生产 EXPLAIN 关联属于后续实验，必须各自建立验收契约，不并入当前已经通过 G4/G10 的结论。
