# 3. 环境与可复现声明

## 环境

G4/G10 的真实端点为 `root@45.202.199.140`，OpenTenBase 5.0 commit `0915c04e4`，Coordinator 端口 `22201`，pgvector 0.8.0，x86-64，3.7 GiB RAM 加 2 GiB swap。端点、版本和拓扑记录在 `PLAN.md` 与运行日志中；本地 PostgreSQL 只用于 SQL 语法和输入校验 smoke，不能替代远端 pgvector 报错核验。

W2 的 20 组 CSV、23 份校验文件和 20 份原始 stderr 均入库。零参数审计的完整输出、SQL 输入和 stderr 位于 `report/figures/data/`，原始端点日志为 `tests/audit-zero-param-20260818.log`。每个证据目录都有 SHA256 清单，报告构建脚本不从 PDF 反向取数。

## 复现原则

先执行 `tests/test_input_validation.sh` 和 `tests/test_memory_model_matrix.sh`，再在授权端点执行 `sql/02_memory_model.sql`、`sql/04_catalog_introspect.sql`、`sql/05_audit.sql` 与 `tools/validate_memory_model.sh`。验证器按 case id 建立独立目录，保存输入、预测、模式、观测、误差、状态和 stderr 路径。`MODE=auto` 在端点不可用时只输出 model-only，绝不把 predicted 写入 observed；`real-threshold` 通过降低 `maintenance_work_mem` 触发同源检查点，必须在结果中标为阈值路径。
